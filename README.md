# MAX-бот: ближайшие точки бесплатного Wi-Fi

Проект рассчитан на Python 3.10+ и библиотеку `maxapi`. База данных хранится локально в SQLite (`wifi_bot.db`).

## Запуск на macOS

1. Откройте папку проекта в VS Code.
2. В терминале VS Code выполните:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

3. Создайте файл `.env` в папке проекта (скопируйте `.env.example`) и укажите новый токен MAX:

   ```env
   MAX_BOT_TOKEN=ваш_новый_токен
   ADMIN_IDS=ваш_ID_администратора
   ```

   Не отправляйте файл `.env` другим людям и не добавляйте его в Git.

4. Запустите бота:

   ```bash
   python bot.py
   ```

## Что изменено

- Добавлен обработчик события MAX `bot_started`: бот отвечает при нажатии кнопки «Начать» и при запуске по deep-link, без ручного `/start`.
- Приглашение на роль обрабатывается из `event.payload`, который MAX передаёт при переходе по ссылке `https://max.ru/<имя_бота>?start=<токен>`.
- Приглашение действует 15 минут и используется один раз. Роли пользователя суммируются, другие роли при выдаче новой не удаляются.
- Неизвестные сообщения обычного пользователя снова предлагают отправить геопозицию.
- Исправлены отступы в `db.py` и блок неизвестных сообщений в `bot.py`.
- Токен не хранится в исходном коде; настройки читаются из `.env`.

## Важно про MAX и polling

В проекте используется long polling. Если у бота была включена подписка на webhook, при запуске она удаляется, чтобы обновления поступали через polling. Не запускайте одновременно webhook-версию и этот polling-процесс.

## Структура

- `bot.py` — события MAX, пользовательские сценарии, меню и роли.
- `db.py` — модели SQLite, расчёт расстояний и валидация данных точек.
- `states.py` — временные состояния диалогов оператора/администратора.
- `.env.example` — пример конфигурации без секретов.
