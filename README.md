# Поиск бесплатного Wi-Fi в MAX

Бот: https://max.ru/wifipoints_digitalkostroma_bot

## Поиск

Пользователь отправляет геолокацию. Бот возвращает до трёх ближайших точек без ограничения радиуса: название, адрес, расстояние и ссылку на Яндекс.Карты. Расстояние рассчитывается по формуле гаверсинусов. Текст не используется вместо геоточки. При пустом реестре бот сообщает, что точки пока не добавлены.

На 25.11.2026 загружены 76 точек Ростелекома из предоставленного JSON. Это имеющаяся часть реестра; дополнительные точки можно импортировать позже. В источнике не было SSID и паролей — они не выдумывались. В текущей пользовательской выдаче SSID, пароль и комментарий не выводятся, хотя могут храниться в записи.

## Управление точками и ролями

- Любой пользователь может искать ближайшие точки.
- Оператор и администратор могут добавлять, редактировать, удалять и просматривать точки.
- Администратор дополнительно создаёт приглашения на роли, снимает роли и просматривает их список. Приглашения действуют 15 минут, используются один раз. Один пользователь может иметь несколько ролей.

Добавление через меню требует одну строку из семи полей:

```text
Название; Адрес; Широта; Долгота; SSID; Пароль; Комментарий
```

Название, адрес и SSID обязательны при ручном вводе. Пароль и комментарий могут быть пустыми, разделители сохраняются. Координаты проверяются по диапазонам широты и долготы. Для редактирования и удаления сначала указывается ID из списка; удаление требует подтверждения.

## Массовая загрузка

На сервере `manage.py wifi import-wifi --file /path/points.json` принимает массив:

```json
[
  {"id": "source-001", "name": "Wi-Fi", "address": "Адрес точки",
   "latitude": 57.77, "longitude": 40.93,
   "ssid": "", "password": "", "comment": "Источник реестра"}
]
```

Импорт, в отличие от ручной формы, допускает отсутствие SSID. Записи обновляются по стабильному `id` источника (в БД префикс `import:`); отсутствующие в новом файле записи автоматически не удаляются. Перед импортом нужна согласованная резервная копия SQLite. Для исходного формата Ростелекома в родительском проекте есть `prepare_wifi_import.py` и `import-rtk-wifi.sh`.

## Код в этом репозитории

`bot.py`, `db.py`, `states.py`, `.env.example` и локальный `requirements.txt` — прежняя отдельная реализация Wi-Fi на maxapi. Она не является текущей развёрнутой версией. Её настройки и поведение нельзя переносить на рабочий runtime без сверки. Текущий запуск описан ниже.

## Реализация и запуск

Рабочая версия находится в общем каталоге `../runtime/`, а не в этом репозитории. Это три отдельных процесса с отдельными БД и конфигурациями. Для воспроизводимого запуска нужен соседний каталог `runtime/`; одного клона этого репозитория недостаточно. Описание переменных окружения, запуска и обслуживания: [запуск и обслуживание](docs/runtime.md).

Стек рабочей версии: Python 3.12 на VDS, aiohttp, Peewee, SQLite. События поступают через HTTPS webhook MAX; входящие события и исходящие сообщения сохраняются в SQLite. Диалоги хранятся в БД, срок состояния — 10 минут. `/start` сбрасывает текущий диалог, `/id` показывает MAX ID, «Отмена» отменяет текущий ввод.

Роли проверяются перед действиями; права выдаются одноразовыми приглашениями либо администратором сервера через `manage.py`. Последнюю роль администратора снять через меню нельзя. Секреты и рабочие БД в Git не сохраняются.

Документация сверена с `runtime/` и согласованными изменениями на 26.11.2026. Тесты и пробные обращения в ботов по указанию владельца не запускаются.
