# Функциональные требования к чат-боту MAX для поиска бесплатного Wi-Fi в Костроме

## 1. Назначение

Чат-бот предназначен для приёма геолокации пользователя и предоставления ссылок на Яндекс.Карты с тремя ближайшими точками бесплатного Wi-Fi в Костроме.

| Компонент | Технология |
|---|---|
| Язык | Python 3.10+ |
| ORM | Peewee |
| БД | SQLite3 |
| Платформа | MAX Bot API |

## 3. Роли и права

Роли: **Пользователь**, **Оператор**, **Администратор**.

Один пользователь может обладать **несколькими ролями одновременно**. Права складываются.

| Роль | Геоточка | Управление точками Wi-Fi | Управление ролями |
|---|---|---|---|
| Пользователь | Да | Нет | Нет |
| Оператор | Да | Да | Нет |
| Администратор | Да | Да | Да |

Первый администратор задаётся через `ADMIN_IDS`.

**Выдача ролей:**
- Роль **Оператор** или **Администратор** выдаётся по одноразовой ссылке, которую создаёт администратор.
- Ссылка действует **15 минут** и может быть использована **только один раз**.
- Снятие ролей выполняет администратор.

## 4. Кнопки меню

Команды не используются. Все действия выполняются кнопками меню MAX Bot API.

Меню формируется из доступных ролей. Если у пользователя только роль **Пользователь**, кнопки меню отсутствуют — взаимодействие происходит отправкой геолокации.

| Роль | Кнопки |
|---|---|
| Пользователь | Нет кнопок |
| Оператор | «Добавить точку», «Редактировать точку», «Удалить точку», «Список точек» |
| Администратор | «Создать ссылку на оператора», «Создать ссылку на администратора», «Снять оператора», «Снять администратора», «Список ролей» |

В диалогах ввода доступна кнопка **«Отмена»**.

Если для действия нужен ID или данные, бот запрашивает их текстом.

## 5. Сценарии использования

### 5.1. Пользователь

| Действие пользователя | Ответ системы |
|---|---|
| Запускает бота | Если ролей нет, назначается роль Пользователь. Бот отправляет: «Отправьте свою геолокацию, и я пришлю 3 ближайшие точки бесплатного Wi-Fi в Костроме.» |
| Отправляет геоточку | «Найдены ближайшие точки Wi-Fi:» и список из 3 ближайших точек. Для каждой точки: название, адрес, расстояние, ссылка на Яндекс.Карты. |
| Отправляет геоточку, когда точек нет | «Точки бесплатного Wi-Fi пока не добавлены.» |
| Отправляет текст, команду или другое сообщение | «Не удалось распознать геоточку. Отправьте свою геолокацию.» |
| Переходит по одноразовой ссылке для получения роли | Если ссылка действительна: «Вам назначена роль {роль}.» Если ссылка истекла или использована: «Ссылка недействительна или истекла.» |

Ссылка на Яндекс.Карты:

> `https://yandex.ru/maps/?pt={долгота},{широта}&z=17&l=map`

Расстояние: до 1000 м — в метрах, от 1000 м — в километрах.

Пример ответа:

> Найдены ближайшие точки Wi-Fi:
>
> 1. Библиотека им. Н.А. Некрасова  
> Адрес: ул. Ленина, 10  
> Расстояние: 350 м  
> Ссылка: https://yandex.ru/maps/?pt=40.9269,57.7679&z=17&l=map

### 5.2. Оператор

| Действие пользователя | Ответ системы |
|---|---|
| Нажимает «Добавить точку» | «Добавление точки Wi-Fi. Отправьте данные одной строкой в формате: Название; Адрес; Широта; Долгота; SSID; Пароль; Комментарий. Пароль и Комментарий можно оставить пустыми. Для отмены нажмите «Отмена».» |
| Отправляет корректные данные | «Точка Wi-Fi добавлена. ID: {id}. Название: {name}. Адрес: {address}.» |
| Отправляет некорректные данные | «Не удалось добавить точку Wi-Fi: {причина}. Проверьте формат и отправьте данные ещё раз или нажмите «Отмена».» |
| Нажимает «Редактировать точку» | «Введите ID точки Wi-Fi для редактирования.» |
| Отправляет ID существующей точки | «Текущие данные: … Отправьте новые данные одной строкой в формате: Название; Адрес; Широта; Долгота; SSID; Пароль; Комментарий.» |
| Отправляет ID несуществующей точки | «Точка Wi-Fi с ID {id} не найдена.» |
| Отправляет корректные новые данные | «Точка Wi-Fi обновлена.» |
| Нажимает «Удалить точку» | «Введите ID точки Wi-Fi для удаления.» |
| Отправляет ID существующей точки | «Удалить точку Wi-Fi ID {id} — «{name}»? Нажмите «Да» или «Нет».» |
| Нажимает «Да» | «Точка Wi-Fi удалена.» |
| Нажимает «Нет» | «Удаление отменено.» |
| Нажимает «Список точек» | Список всех точек Wi-Fi или «Точки Wi-Fi пока не добавлены.» |
| Нажимает «Отмена» | «Действие отменено.» |
| Пытается использовать кнопку администратора | «Недостаточно прав. Кнопка доступна только администраторам.» |

### 5.3. Администратор

| Действие пользователя | Ответ системы |
|---|---|
| Нажимает «Создать ссылку на оператора» | «Ссылка для назначения роли оператора: {link}. Действует 15 минут. Отправьте её пользователю.» |
| Нажимает «Создать ссылку на администратора» | «Ссылка для назначения роли администратора: {link}. Действует 15 минут. Отправьте её пользователю.» |
| Нажимает «Снять оператора» | «Введите ID пользователя, у которого нужно снять роль оператора.» |
| Отправляет ID | «У пользователя {user_id} снята роль оператора.» Если роли нет: «У пользователя {user_id} нет роли оператора.» |
| Нажимает «Снять администратора» | «Введите ID пользователя, у которого нужно снять роль администратора.» |
| Отправляет ID | «У пользователя {user_id} снята роль администратора.» Если роли нет: «У пользователя {user_id} нет роли администратора.» |
| Пытается снять роль с последнего администратора | «Нельзя снять роль администратора с последнего администратора.» |
| Нажимает «Список ролей» | «Список пользователей и ролей: …» |
| Нажимает «Отмена» | «Действие отменено.» |
| Пытается использовать кнопку без роли администратора | «Недостаточно прав. Кнопка доступна только администраторам.» |

## 6. Нефункциональные требования

1. Python 3.10+, Peewee, SQLite3, MAX Bot API.
2. Кнопки реализуются через клавиатуру MAX Bot API.
3. Состояние диалогов хранится в памяти и сбрасывается по «Отмена» или через 10 минут.
4. Расстояние считается по формуле гаверсинусов.
5. Радиус поиска не ограничен.
6. Первый администратор задаётся через `ADMIN_IDS`.
7. Ошибки валидации возвращают конкретную причину.
8. Рекомендуется логирование действий операторов и администраторов.
9. Данные хранятся в SQLite3 через Peewee.
10. Одноразовая ссылка для выдачи роли действует 15 минут и может быть использована только один раз. Токен ссылки уникален.

## 7. Критерии приёмки

1. При запуске бот назначает Пользователя, если ролей нет, и просит геолокацию.
2. Бот принимает только геоточку.
3. Текст, команды и другие сообщения не принимаются как координаты.
4. Поиск идёт по всем точкам без ограничения радиуса.
5. Возвращаются 3 ближайшие точки со ссылками на Яндекс.Карты.
6. Если точек меньше 3 — возвращаются все.
7. Если точек нет — сообщение «Точки бесплатного Wi-Fi пока не добавлены.»
8. Один пользователь может иметь несколько ролей.
9. Роль Оператор или Администратор выдаётся по одноразовой ссылке, созданной администратором.
10. Ссылка действует 15 минут и используется один раз.
11. При переходе по недействительной ссылке бот сообщает: «Ссылка недействительна или истекла.»
12. Оператор управляет точками Wi-Fi через кнопки меню.
13. Администратор управляет ролями и точками Wi-Fi через кнопки меню.
14. Пользователь и оператор не управляют ролями.
15. Пользователь не управляет точками Wi-Fi.
16. Данные хранятся в SQLite3 через Peewee.
17. Все сообщения соответствуют таблицам раздела 5.
